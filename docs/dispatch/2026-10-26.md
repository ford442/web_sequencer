```
Title: fix(pitch): noteToMidi accepts flats, double accidentals and octave -1; garbage never becomes MIDI 0 (#1493 slice 1)

## Context / motivation

Foundation work under #1493 ("one note parser and one frequency for every engine"), which replaces the mistakenly-closed #1466. Hybrid-engine stability is the active focus area; this is the data-path half of it — the same name must mean the same pitch on the WebGPU, WASM, Pyodide and native-fallback paths, live and offline.

`noteToMidi` in `src/utils/musicTheory.ts` is:

    const match = note.match(/([A-G]#?)(\d+)/);
    if (!match) return 0;

So `Eb3`, `Bb3`, `Cb4`, `F##3` and `C-1` all return 0 — MIDI 0, about 8.18 Hz — and that value flows into every engine. The function has 38 call sites in 20 non-test files (`useStepHandler.ts`, `audioPlayback/{playSynth,playDrum,noteControls}.ts`, `samplerPlayback/{playSamplerVoice,samplerControls}.ts`, `piano-roll/model/rollModel.ts`, `sequencer/noteFx/chain.ts`, `SequencerRow.tsx`, `MelodicSequencerRow.tsx`, `AdvancedNoteSelector.tsx`, `appState/{usePatternHandlers,useKeyboardHandlers}.ts`, `audio/wam/WamHost.ts`, `constants.ts`, `importers/rbs/{importer-types,rbsEncoders}.ts`, `importers/smf/SmfExporter.ts`, `workers/renderer.worker.ts`). The AI-song importer's validator accepts `[A-G][#b]?` and `test-fixtures/ai-song/full.json` carries `Ab1`, `Bb3`, `Bb4`, `Eb3`, `Eb4`, so a fixture the importer calls valid renders five notes at 8 Hz. `src/utils/__tests__/musicTheory.test.ts` asserts only `C4` and `A4`.

This issue is the parser and its callers only. Hz-on-the-native-event (steps 3–4 of #1493) lands after #1492 and is out of scope here.

## Proposed approach (first pass — expand before implementing)

1. Parser. One exported regex constant and one `parseNoteName(name): { pitchClass: 0..11, octave: -1..9, midi: 0..127 } | null` in `musicTheory.ts`. Accept `[A-G]` + a run of `#`, `b`, `♯`, `♭` (fold `##`/`x` to +2, `bb` to −2; `Cb4` → 59, `B#3` → 60), octave `-1`..`9`, optional surrounding whitespace, case-insensitive letter. Reject anything else with `null`. `noteToMidi` becomes a thin wrapper that throws a typed `InvalidNoteNameError` (or returns `null` — see open questions); it never returns 0 for garbage. `midiToNote` keeps the sharp spelling; round-trip is "parse, then spell with sharps".
2. Callers. Audit the 38 sites. Any site that currently reads `0` as "rest" or "no note" gets an explicit rest check before parsing (the sequencer's rest sentinel, not the parser's failure value). Any site that could receive user or file input (AI-song importer, RBS importer, SMF exporter, WAM host, keyboard handler) must handle the failure explicitly and report it (the importers already have a report path). Hot paths (`useStepHandler`, `playSynth`, `rollModel`) must not allocate per call — keep the fast path a single regex exec with no intermediate objects, or memoise on the name string.
3. Share the regex with the AI-song validator (`src/importers/ai-song/**`) so "valid" and "parseable" are the same predicate; the JSON Schema's pattern (`docs/schemas/`, #1471) must match it too, and the existing schema drift check must still pass.
4. Tests. Table-driven cases in `musicTheory.test.ts`: `Eb3`=63, `Bb3`=58, `Cb4`=59, `B#3`=60, `F##3`/`Fx3`=67, `Ebb4`=62, `C-1`=0, `G9`=127, `B9`→out of range (decide: clamp vs reject), `nope`/`H4`/`C`/`C10`→invalid, whitespace and lowercase. An AI-song render test (there is a render/agreement harness from #1467/#1471) that renders `test-fixtures/ai-song/full.json` and asserts no partial below 20 Hz from those five notes. A caller test per behaviour change (rest handling in the step handler; importer report on an invalid name).

## Acceptance criteria (rough — refine)

- `noteToMidi('Eb3') === 63`, `noteToMidi('Cb4') === 59`, `noteToMidi('C-1') === 0` only because that note is MIDI 0, and `noteToMidi('nope')` does not return 0.
- The AI fixture's flat note names play at the frequencies `tunedNoteToFrequency` returns; the render test proves no 8 Hz partial.
- No caller treats the parser's failure value as a rest; rests are decided before parsing.
- The AI-song validator, the JSON Schema and the parser agree on one pattern; `pnpm run check:ai-song-schema` passes.
- `pnpm exec tsc -b`, `pnpm run lint`, `pnpm run lint:ratchet` (counts only go down), `CI=true pnpm run test:unit`, `pnpm run build` all green. No `eslint-disable`, no baseline raise, no test skip.
- Files touched stay inside: `src/utils/musicTheory.ts`, `src/utils/__tests__/`, the 20 caller files, `src/importers/ai-song/**`, `docs/schemas/**`, `test-fixtures/ai-song/**`. Nothing in `src/engines/`, `src/midi/clock/`, `tests/*.spec.ts`, `scripts/`, `emscripten/`.

## Open questions for Noah

1. Throw vs `null` from `noteToMidi` on garbage? Throwing is louder and matches #1493's "callers must not hear MIDI 0"; `null` forces every one of 38 call sites to branch. A middle path: `parseNoteName` returns `null`, `noteToMidi` throws, and the hot-path callers use `parseNoteName` directly.
2. Which callers really use 0 as a rest sentinel today? The RBS encoders and SMF exporter look like they may write 0 as "no note"; confirm before changing their behaviour.
3. Octave range: MIDI 0–127 means `C-1`..`G9`. Reject `G#9`+ or clamp? The piano roll and SMF both cap at 127.
4. Should `midiToNote` grow an optional `prefer: 'sharp' | 'flat'` for display, or is that a UI concern for later?
5. Does the AI-song JSON Schema (#1471) already constrain note names? If so, is it the sharps-only pattern (then it is wrong twice) or the `[#b]?` one (then doubles are a schema change)?
```
