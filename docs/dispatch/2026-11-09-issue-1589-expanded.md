## Decisions (read these first)

1. **No new playhead attribute. No overlay element. Reuse `.is-current`.** All three reviewers converged here once the tree was read: the playhead is already imperative (`SequencerRow.tsx:85-86`, `MelodicSequencerRow.tsx:98-101` toggle `is-current` via `classList` inside `requestAnimationFrame`; two DOM writes per row per step change). `data-playhead` would duplicate that state for nothing (Gemini: 4 writes instead of 2; Grok: attribute selectors are not hash-indexed like classes, so `[data-playhead]` across 128–256 elements is the slower hot path). gpt-oss's overlay-plus-CSS-variable idea (Alternative A) loses the per-step glow / cap / LED visuals, needs new markup in `SequencerRow.tsx`, and a new file under `src/components/sequencer/` fails `noStaleSequencerSplit.test.ts`, which pins the exact ten-file list of that directory. Three tests pin the class name: `SequencerLength.test.tsx:95-96`, `tests/helpers/rbs-e2e.ts:73`, `tests/live-issue-triage.spec.ts:285`. So the step grid is **CSS-only**, keyed on the existing `.is-current` and the existing `aria-pressed="true"` (`SvgStep.tsx:91`, `MelodicStep.tsx:280`; `SEQUENCER_STYLES` already uses `.svg-step[aria-pressed="true"].is-current` at `constants.ts:38`). **No `data-on` either**: `aria-pressed` already carries the active state.
2. **Step-grid CSS goes in `SEQUENCER_STYLES` (`src/components/sequencer/constants.ts:10-50`), not `hyphon-theme.css`.** That template string holds every `.is-current` rule (`.step-glow` / `.step-cap` / `.step-led` / `.automation-step.is-current`) and is injected by both `App.tsx:87` and `MainSequencer.tsx:252`. Add `[data-chassis="white"] .svg-step …` rules there, restricted to `fill` / `stroke` on `.step-cap` and `.step-led`. **Never add `filter` or animated `box-shadow` to `.svg-step`** — the existing recalc cost is the `filter: drop-shadow` on focus and the 120 ms keyframes, not the class write.
3. **Reduced motion is already global.** `src/accessibility.css:15-23` sets `animation-duration: 0.01ms` and `transition-duration: 0.01ms` on `*, *::before, *::after` under `prefers-reduced-motion: reduce`. The owner's "no glow pulsing" requirement is therefore met by any CSS `animation` / `transition`; the only thing the global rule cannot cancel is a **static** glow, which is fine to keep. Do not add a second grid-level reduced-motion block; add one line to `hyphon-theme.css`'s existing block (line ~350) only for `transform` on press, which the global rule does not touch. Inline `transition` styles (`SvgStep.tsx:91`, `MelodicStep.tsx:256,287`, `LiveKeyboard.tsx:222`) are also covered by the global `*` rule; leave them.
4. **Tailwind stays config-file.** `package.json` pins `tailwindcss ^3.4.6` and `src/index.css` uses `@tailwind base/components/utilities` after `@import './styles/hyphon-theme.css'`. New tokens go in `hyphon-theme.css` and, if a utility is wanted, in `tailwind.config.js` `theme.extend` exactly like `hyphon.*` today. `@theme` is Tailwind 4; not applicable (Grok point 3).
5. **Pads: `--pad-color` hex per config entry + `data-hit`.** `DrumPads.tsx:15-22` has Tailwind class names only (`color: 'bg-red-500'`), no hex, so the owner's `.pad { --c: var(--pad-color, …) }` has nothing to read. Add an `accent` hex to each `PadConfig`, set `style={{ '--pad-color': pad.accent }}` on the button, add `data-hit={isActive || undefined}`, keep every existing class so the dark theme is unchanged. Pad glow under the white chassis: a `::after` with `opacity` transition, not an animated `box-shadow` (gpt-oss; GPU-composited, and the global reduced-motion rule neutralises the transition).
6. **Keys: `data-key` + `data-down` on existing elements; fills via CSS; LED = "note in current scale".** `PianoKey` (`LiveKeyboard.tsx:173-300`, memoised, `aria-pressed={isActive}` on the `<g role="button">` at :195-199) draws the body rect with `fill={isBlack ? '#0f172a' : '#f8fafc'}` (:234) and the face rect `fill={isActive ? activeColor : …}` (:242). Author CSS overrides SVG presentation attributes at any specificity, so `[data-chassis="white"] [data-key="white"] .key-body { fill: var(--key-white) }` works without removing the attributes, and without the attribute the dark theme is byte-identical. Put `data-key="white|black"` and `data-down={isActive || undefined}` on the `<g role="button">`; add class names `key-body` / `key-face` to the two rects. The per-key LED: `KeyboardNode.tsx` adds `'currentScale'` to `KEYBOARD_KEYS` (it is an `AppState` field, `useAppState.tsx:213`), computes `getScaleNotes(currentScale)` (`src/utils/musicTheory.ts:228`) once in a `useMemo`, and passes `scaleNotes?: Set<string>` to `LiveKeyboard` → `PianoKey` as `inScale: boolean`. One recompute per scale change; the existing memo means only keys whose `inScale` flips re-render. The existing top-right `keyboard-note-led` (`LiveKeyboard.tsx:495`) stays as it is. The `KeyboardGuide` schematic in the same file (:77-110, hard-coded `#1f2937` fills) is a help dialog, not the key bed: out of scope, say so in the PR.
7. **Accessibility (Grok point 6):** LED circles and glow pseudo-elements get `aria-hidden="true"`; under `@media (forced-colors: active)` the pad-hit and playhead states need a non-shadow cue (`outline: 2px solid Highlight`), because forced-colors mode drops `box-shadow`.
8. **Playwright: computed-style assertions are the gate; one screenshot is an artifact.** Gemini and Grok both say committed baselines churn across runners and fonts for a page this text-heavy; promote the screenshot to a gate only after it has been stable on the CI runner for a week. If a screenshot is committed anyway: chromium-linux only, `animations: 'disabled'`, fixed `deviceScaleFactor`, wait for `document.fonts.ready`, `snapshotPathTemplate` without `{platform}`.
9. **`color-mix(in srgb, a, b)` and unprefixed `mask` are safe** for current Chrome / Firefox / Safari incl. iOS 16.2+ / 15.4+ (Grok points 1); use two-colour mixes only.

## Ecosystem notes (Grok, 2026-11)

`color-mix()` two-colour and unprefixed `mask` are Baseline widely available (Chrome 111+/120+, Firefox 113+/53+, Safari 16.2+/15.4+). Attribute selectors are not hash-indexed like classes; keep them off the per-tick path (done: none added). Tailwind 4 is CSS-first but this repo is 3.4.x; config-file tokens are correct here. React 19: ref callbacks may return a cleanup, so any touched ref callback uses a block body (none are touched by this plan). `forced-colors: active` drops `box-shadow`; states conveyed only by glow need an outline fallback.
