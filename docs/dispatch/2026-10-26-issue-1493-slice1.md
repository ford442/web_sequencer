## Design (decided)

One parser, three entry points, in `src/utils/musicTheory.ts`:

```ts
/** Letter, then accidentals, then octave. Uppercase letter only: a lowercase
 *  `b` is always a flat, so "bb3" can only mean B-flat 3. */
export const NOTE_NAME_SOURCE = '^\\s*([A-G])(#{1,2}|x|b{1,2}|♯{1,2}|♭{1,2})?(-1|[0-9])\\s*$';
export const NOTE_NAME_REGEX = new RegExp(NOTE_NAME_SOURCE);   // no flags: the same source goes into the JSON Schema

export class InvalidNoteNameError extends Error { readonly noteName: string; … }

/** Hot path. 0..127, or -1 for empty / garbage / out of range. One regex exec, no allocation. */
export function tryNoteToMidi(name: string): number
/** Boundary path. Structured result or null. Allocates. */
export function parseNoteName(name: string): { pitchClass: number; octave: number; midi: number } | null
/** Throws InvalidNoteNameError. Never returns 0 for garbage. */
export function noteToMidi(name: string): number
```

Decisions, with the reasoning each reviewer supplied:

1. **Three tiers, not one.** `tryNoteToMidi` keeps the per-step / per-voice paths at exactly today's cost (one `exec` on a ≤ 5-char string; that is what runs now) and returns a primitive, so there is no object allocation on the audio-adjacent hot path (gpt-oss failure #8). `parseNoteName` is for importers and UI. `noteToMidi` throws so that any unmigrated or future call site fails loudly instead of emitting MIDI 0 — but no hot-path caller may use it (gpt-oss failure #2: a throw inside `renderer.worker.ts` is swallowed by `self.onmessage` at `:132`, which has no try/catch and no error post).
2. **No memo cache in this slice.** The bounded-`Map` idea (Gemini) protects against something that does not exist yet; user-typed garbage would grow it (gpt-oss #3). Measure first; the regex is already the cost today.
3. **Rest is decided before parsing, by the existing convention: no note string (`''` / `undefined`) means rest.** The parser's `if (!note) return 0` is today's hidden rest fallback. It becomes `-1` / `null` / throw. There is no `REST` MIDI constant (gpt-oss alternative 1 rejected for this slice: `step.note` is the persisted format in every pattern, importer and exporter; a parse-once, numbers-everywhere model is a data-model change that belongs with #1494 / #1497, not a parser fix). `C-1` is a real note and is MIDI 0; callers that compare MIDI to 0 to mean "unset" are listed below and are changed to check the string.
4. **Out of range is rejected, never clamped.** `G#9`+ and `Cb-1` → `-1` / `null` / throw. Clamping would transpose silently (Gemini, Grok). Mixed accidentals (`#b`) are rejected by the regex shape.
5. **Spelling:** `midiToNote` stays sharps (C4 = 60, C-1 = 0, G9 = 127 — the SPN / tonal / Tone.js / WEBMIDI.js convention; Ableton / Logic / Yamaha users see a display octave offset only). Round-trip is "parse, then spell with sharps". No `prefer: 'flat'` option in this slice.
6. **Unicode `♯` / `♭` and `x` are accepted and folded**; the regex has no `i` / `u` flag so the identical source string is valid inside a JSON Schema `pattern` (Gemini). Lowercase letters are rejected (see the `bb3` note above).
7. **One regex everywhere.** `renderer.worker.ts` imports the parser instead of carrying a copy (Vite bundles `?worker` modules; the worker already type-checks as part of the app project). `noteColors.ts` and `useLyricHandlers.ts` use `parseNoteName`. `isValidNote` becomes `parseNoteName(note) !== null`, and `gen-ai-song-schema.ts` imports `NOTE_NAME_SOURCE` (it already imports from `src/importers/ai-song/versioning`). Schema octave range widens from `[0-8]` to `-1..9`; that is a schema change and the committed `docs/schemas/ai-song.schema.json` is regenerated in the same PR so `pnpm run check:ai-song-schema` stays green.
8. **One `tunedNoteToFrequency`.** `src/constants.ts:246` becomes a re-export of the `musicTheory.ts` one (same signature; `VoiceManager.ts:2` keeps its import path). Check `src/__tests__/constants.test.ts` first: the `constants.ts` version returns the 2-decimal table value for 12-TET on-table names and the computed value off-table; if the test asserts the rounded value, keep the table lookup inside the shared function for 12-TET so numbers do not move. This is the "one frequency for every engine" half that costs nothing.
