Title: Activate the master PCF endpoint so RBS-imported master PCF lanes are audible (live + offline)

## Context / motivation
RBS import already parses ReBirth's master Pattern-Controlled Filter data and `src/audio/automation/AutomationScheduler.ts` routes the three master PCF parameters — `pcfCutoff`, `pcfResonance`, `pcfEnvAmount` — to `audioEngine.pcfEffect`. But nothing constructs a `PcfEffect` in either graph: `src/engines/PcfEffect.ts` exists, its worklet is imported with `?worker&url`, and the release-dist gate observed on 10-26 that the `pcf-processor` chunk is never emitted because no reachable code path imports it. So every imported ReBirth song's master-filter sweep is a silent no-op, live and in offline render / stems. This is the one item in the 11-01 openrb-338 wave that is pure Hyphon code with no licence question, and it is the prerequisite for #1539 (PCF as a routable filter in the patch bay).

Active focus areas this touches: hybrid audio-engine fallback chain (the effect must degrade cleanly when the worklet fails to load), WASM pipeline stability (one more worklet chunk through the release gate), RBS fidelity.

## Proposed approach (first pass — expand)
1. Live graph: in the master-bus assembly under `src/hooks/audioEngine/` (where the master loudness stage and mix bus are inserted), construct a `PcfEffect` once the AudioContext is running, insert it immediately before the master loudness / limiter stage, and expose it as `audioEngine.pcfEffect` — the field `AutomationScheduler` already writes to. Default state must be bypass-equivalent (cutoff fully open, env amount 0) so songs without PCF lanes are bit-identical to today; confirm with an offline-render golden.
2. Offline graph: `src/audio/offline/compileOfflineGraph.ts` builds the offline chain and `offlineLaneAutomation.ts` resolves lanes; add the same PCF stage at the same position and feed it the resolved `pcf*` lanes so render, stems and freeze match live.
3. Failure path: if the worklet module fails to `addModule` (the fallback-chain case), log through the existing engine-degradation store and pass audio straight through; the scheduler must not throw on a null `pcfEffect`.
4. Gate: the `pcf-processor` chunk becomes reachable, so `scripts/check-release-dist.mjs`'s worklet count goes 8 → 9 and the chunk must be self-contained (no runtime import/export). Update `dist-budget.json` only if the new chunk exceeds the per-worklet budget, in its own commit, with the number.
5. Docs: one paragraph in the patch-bay / graph doc (`docs/audio-engine/` or `docs/arrangement.md`, wherever the master chain is described) stating the insertion point and that PCF is pre-limiter.

## Acceptance criteria (rough)
- Import an RBS fixture with master PCF lanes (there is one under `test-fixtures/` used by `tests/rbs-automation.spec.ts`; do not edit that spec): with the pattern playing, the master signal's spectral centroid moves with the lane (an offline render + FFT assertion in Vitest, not a listening test).
- Offline render / stems of the same song produce the same modulation (render-vs-live golden within tolerance).
- A song with no PCF lanes renders bit-identically to `main` before the change.
- Per-voice 303 filter automation (`cutoff` / `resonance` on `tb303A` / `tb303B` targets) is unchanged — existing tests pass.
- Worklet load failure degrades to pass-through with a logged reason; no exception on the scheduler path.
- `pnpm run build` passes the release-dist gate with 9 worklet chunks.
- `tsc -b`, `pnpm lint`, `lint:ratchet`, `CI=true test:unit` green; no baseline raise.

## Open questions for Noah
- Insertion point: pre-limiter on the master bus (ReBirth's topology) or as a send-able node now so #1539 is a UI change only?
- Does the Mix Bus (C++ `mix_bus.cpp`) own the master chain in the offline path, and if so should PCF be a native stage there rather than a TS worklet, for sample parity with live?
- Should RBS import flip a visible "Master PCF" indicator / knob so the user can see the lane is active, or stay invisible until #1539?
- Default when no lane is present: hard bypass (node removed) or neutral parameters (node in chain)? Bypass is safer for parity; neutral is simpler for #1539.
