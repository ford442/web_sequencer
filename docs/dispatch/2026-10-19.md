**Title:** `fix(music-theory): noteToMidi rejects flats, double accidentals and octave −1 — every Eb/Bb in an AI song plays at MIDI 0, live and offline`

```markdown
## Context / motivation

`noteToMidi` in `src/utils/musicTheory.ts:6` is the one note-name parser in the app:

    const match = note.match(/([A-G]#?)(\d+)/);
    if (!match) return 0;

It accepts sharps only. `Eb3`, `Bb3`, `Cb4`, `F##3`, `E#3` and `C-1` all return 0 → MIDI 0 → 8.18 Hz. The regex is unanchored, so `Eb3` does not even fail loudly: it fails to match at `E`, then finds nothing, and returns the "no match" value — which is also the value of a real note (C-1). Twelve call sites use it (live: `hooks/audioEngine/audioPlayback/noteControls.ts`, `playSynth.ts`, `samplerPlayback/playSamplerVoice.ts`, `useStepHandler.ts`; offline: `utils/renderAudio.ts`, `utils/patternRenderer.ts`, `workers/renderer.worker.ts`; UI: `components/piano-roll/model/rollModel.ts`, `AdvancedNoteSelector.tsx`; `sequencer/noteFx/chain.ts`; `importers/smf/SmfExporter.ts`; `constants.ts`), so the bug is not offline-only as PR #1463 reported — it is everywhere a note string becomes a pitch.

The AI-song importer validates note names with `/^[A-G][#b]?[0-8]$/` (`src/importers/ai-song/AISongImporter.ts:22`), i.e. it explicitly promises flats work, and `test-fixtures/ai-song/full.json` contains `Ab1`, `Bb3`, `Bb4`, `Eb3`, `Eb4`. Every one of those renders as sub-audio today. Any LLM writing a song in Eb minor produces a silent bass line. This sits squarely in the AI-song workflow (#1385–#1388) and the offline-render fidelity work (#1384 / #1463).

## Proposed approach (first pass — Noah will expand)

1. **Failing tests first** in `src/utils/__tests__/musicTheory.test.ts` (create if absent): table of `['Eb3', 51], ['Bb3', 58], ['Cb4', 59], ['B#3', 60], ['F##3', 55], ['C-1', 0], ['G9', 127], ['H3', null], ['', null]`; plus one AI-song importer test that imports a pattern with `Eb3` and asserts the live step handler receives 51 (not 0) via the existing mocks in `src/hooks/__tests__/useStepHandler.trigger.test.ts`'s style.
2. **One parser, strict and anchored:** `parseNoteName(note): number | null` in `musicTheory.ts` — `^([A-G])(#{1,2}|b{1,2}|x)?(-?\d+)$`, octave −1..9, result clamped/validated to 0..127, `null` otherwise. `noteToMidi` becomes a thin wrapper that keeps its current "0 on garbage" contract for the hot paths but logs once per distinct bad name in dev (`import.meta.env.DEV`), so a bad name is visible without an audio-thread cost.
3. **Round-trip helpers:** `midiToNote` stays sharps-only (that is what the UI shows) and a new `normalizeNoteName('Eb3') === 'D#3'` is used at the import boundaries (AI importer, RBS importer if it carries names, SMF if applicable) so stored songs are canonical and the piano roll / note selector never see a flat.
4. **Audit the 12 call sites** for anything that does its own parsing or special-cases `0`; fix only the ones that mishandle the `null` / 0 distinction.

- [ ] `test-fixtures/ai-song/full.json` imported through `AISongImporter` yields no step whose resolved MIDI is 0 unless the name is literally `C-1`.
```
