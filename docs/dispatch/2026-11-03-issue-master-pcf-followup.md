# Master PCF follow-up — close the acceptance gaps left by #1554 / #1562 (expands #1535)

_Written 2026-11-03 from the three expansion prompts in `docs/dispatch/2026-11-02.md` §C (Gemini Pro read the tree; gpt-oss-120b stress-tested the plan; Grok checked the ecosystem), each claim re-verified against `main` `b6434bf`. The 11-02 §B draft assumed no `PcfEffect` was constructed; that was true at 13:00Z on 11-02 and false by 00:32Z on 11-03, when #1554 landed. #1535 is closed. This is the follow-up._

## Context

#1554 inserted the master PCF (`masterPanner → masterPcf → masterLimiter`, live via `createMasterPcf` in `engineLifecycle.ts`, offline via `compileOfflineGraph({ masterPcf })`), #1561 added the openrb low-pass mode, #1562 made the PCF a placeable patch-bay node with a live panel. The owner closed #1535 as completed at 00:33Z. Of the original acceptance list, "audible on the master bus" was proved once by hand (headless Chromium, noise RMS 0.58 → 0.20 at a 200 Hz lane, in the #1554 body) and not by a test; the failure path logs to the console but never reaches the engine-degradation store; the release gate does not know the new worklet exists; and two behaviours of the lane path can silence or colour the whole mix without anything saying so. None of this needs a redesign. Each item is one test or one guard.

Ecosystem check (Grok, 2026-11): nothing invalidates the design. `renderSizeHint` is Chromium-only and buggy on non-power-of-two sizes, so keep the 128-frame quantum; OfflineAudioContext + FFT assertions remain the deterministic parity proof; Vite 8 `?worker&url` chunks still need the self-containment gate; headless Firefox still needs the PulseAudio null sink and WebKit has a GStreamer crash on AudioContext pages on Ubuntu 26.04 (fix in Playwright main, not yet released), so do not move audibility into E2E.

## Verified gaps (file:line on `b6434bf`)

1. **No automated audibility proof.** `src/__tests__/PcfProcessor.test.ts` drives the processor directly (Nyquist tone, `uses automation cutoff when set`); `src/audio/offline/__tests__/compileOfflineGraph.test.ts:259` checks the stage is wired; neither renders a song through `compileOfflineGraph` and measures the output. The RBS fixture with a real master filter lane, `test-fixtures/rbs/generated/generated_v20_trak_filter_automation.rbs`, is on disk and referenced by nothing.
2. **Worklet failure never reaches the degradation store.** `src/audio/pcf/masterPcf.ts:39` `console.warn`s and returns `null`; `src/audio/pcf/pcfInsert.ts` does the same for placed PCFs. `src/stores/engineDegradationStore.ts` (`engineDegradationStore.report`) is how every other fallback reaches `EngineDegradationBanner`. The scheduler already survives `null` (`AutomationScheduler.ts` master case returns), so this is reporting only.
3. **Release gate does not list the new worklets.** `scripts/check-release-dist.mjs` `REQUIRED_WORKLET_PROCESSORS` is the eight pre-PCF names; `pcf-processor` and `openrb-lowpass-processor` are absent. The count check only fails when emitted chunks drop *below* the list length, so a build that silently loses the PCF chunk still passes. Note the name check greps the concatenated bundle and `PcfEffect.ts` already contains the string `'pcf-processor'`, so adding the name alone is a weak lock; the entry-based classifier from #1509 is the real one. Do not hand-bump a count: the `?worker&url` scan already sees ten stems.
4. **A cutoff lane parked at 0 is a 20 Hz low-pass of the entire mix.** `laneResolver.ts:120–124` maps lane 0 → `pcfMidiNormToHz(0)` = 20 Hz; `pcf-processor.ts:393` bypasses only while `automationCutoffHz < 0`. Any `master.pcfCutoff` lane whose points sit at 0 (an RBS song with the PCF pattern off but an automation lane present, or a lane a user drew and left) mutes drums, choir and synths alike, and the master analyser (`masterGain → masterAnalyser`, upstream of pan/PCF/limiter) keeps moving, so the meters say the engine is fine. #1554's own follow-up note is the sibling: with lanes only and no resonance lane, the default resonance 40 (Q ≈ 10, `pcf-processor.ts:93`, `PcfEffect.ts:73`) adds a peak near the top of the band and noise RMS rose above bypass.
5. **The cutoff curve exists twice.** `laneResolver.ts:105` `pcfMidiNormToHz` = `20 · 1000^v`; the worklet cannot import it and carries `midiToHz` (`pcf-processor.ts:9,152`). They agree today. A drift is a live-vs-offline cutoff error, not a throw.
6. **A song imported before the engine runs loses its pattern PCF.** `applyImportedEngineState.ts:39` returns `false` when `audioEngine.pcfEffect` is null; `useSongStorage.ts:404,882` call it at load time only. Verify: import with `importPcfAsFilter: true` before INITIALIZE SYSTEM, then start the engine — is `song.pcfFilter` applied?
7. **Freeze bypasses the master PCF by design; say so in the UI.** `trackFreezer.ts:223` `freezeThroughPatch` passes no `masterPcf`; `stemExport.ts:403` plays it only for `masterChain: 'live-patch'`. #1554 documents this (`automation.notRendered` + reason). A frozen track compared to live playback will show no sweep; the freeze dialog should surface the `notRendered` reason rather than leave it in the report object.
8. **Two stock-chain constants omit the node.** `defaultElectribeGraph.ts:269` `MASTER_CHAIN_ORDER` and `:280` `MASTER_CHAIN_CONNECTIONS` still end `masterPanner → destination`, and `compileGraph.test.ts:99–113` asserts them against themselves. The compiled edges (`:210–211`) and `MASTER_CHAIN_ORDER_WITH_PCF_AND_LIMITER` (`:256`) are right. Decide whether the plain constants mean "stock chain without optional worklets" (then rename or comment) or are stale.

## Proposed approach

- **A. Audibility test (Vitest, integration tier if it needs the real worklet; otherwise the unit-tier processor harness).** Parse `generated_v20_trak_filter_automation.rbs` with `RbsImporter`, resolve `master.pcfCutoff` with `resolveMasterPcfTimeline`, render bright noise or a saw through `compileOfflineGraph({ masterPcf: { timeline, tempo } })`, and assert the spectral centroid (`src/utils/fft.ts` `calculateSpectralCentroid` or `src/agent/audioMetrics.ts` `spectralCentroid`) of the closed-lane bar is below the open-lane bar by a documented ratio. Second assertion: a render with `masterPcf` omitted equals a render with `{ timeline: [] }` sample for sample (both bridge; `masterPcfRequested` is false). Do not use a live-vs-offline sample diff: live delivery is `setTimeout` per step and the processor smooths over ~one block, so only a centroid ratio is stable.
- **B. Degradation report.** In both `catch` paths (`masterPcf.ts`, `pcfInsert.ts`) call `engineDegradationStore.report(...)` with the existing worklet category, keep returning `null`; extend `masterPcf.test.ts:67` and `pcfInsert.test.ts:304` to assert the report.
- **C. Gate.** Add `pcf-processor` and `openrb-lowpass-processor` to `REQUIRED_WORKLET_PROCESSORS` after a real `pnpm run build` shows both as separate self-contained `<stem>-<hash>.js` chunks; extend `src/__tests__/checkReleaseDist.test.ts` with a fixture that drops the PCF chunk and expect a failure. Touch `dist-budget.json` (`largestWorkletChunkMaxBytes` 36000) only if the measured largest worklet chunk exceeds it, in its own commit, with the number.
- **D. Lane-at-0 guard + default Q.** Two options, pick one in the PR: (i) treat a `master.pcfCutoff` lane whose every point is 0 as "no lane" in `createPcfLaneWatcher` / `resolveMasterPcfTimeline` (clear the override, log once); (ii) keep the mapping but make the Engine HUD / `EngineStatusPill` show "master PCF: 20 Hz" while an override is below, say, 60 Hz. (i) is safer for imports; (ii) is honest for users who drew the lane. Separately, measure ReBirth's resting PCF resonance (the openrb-338 extraction from #1559 is bit-exact and can answer this) and set the lane-only default to match.
- **E. Curve drift test.** One unit test that imports both functions (the worklet one through the existing processor test harness) and compares them at 0, 0.25, 0.5, 0.75, 1 to 1e-9.
- **F. Import-before-engine.** Reproduce item 6; if it loses `pcfFilter`, re-apply the current song's PCF in `engineLifecycle` right after `setMasterPcf(masterPcf)` (one call to `applyPcfFilterToEffect`).
- **G. Docs.** `docs/audio-engine/master-pcf.md` already states post-pan / pre-limiter and the bridge-on-failure rule. Add: live keeps a bypassed node while offline omits it unless requested; freeze and dry stems never run it; the lane-at-0 rule from D.

## Acceptance criteria

- A Vitest run proves the master PCF is audible on an RBS fixture's master lane (centroid ratio asserted, numbers in the test), and proves the no-lane render is bit-identical to the pre-PCF render path.
- Worklet load failure for the master PCF and for a placed PCF appears in `engineDegradationStore` with a reason, and the scheduler path does not throw (existing null guard, now tested together with the report).
- `scripts/check-release-dist.mjs` fails a build whose `pcf-processor` or `openrb-lowpass-processor` chunk is missing or not self-contained; `checkReleaseDist.test.ts` covers it.
- A `master.pcfCutoff` lane at 0 can no longer silently low-pass the mix to 20 Hz (option D-i), or the HUD says it is doing so (D-ii); the choice and the ReBirth resting-Q measurement are in the PR.
- `pcfMidiNormToHz` and the worklet's `midiToHz` are asserted equal.
- Item 6 is either shown not to reproduce or fixed with a test.
- Per-voice 303 filter automation (`open303ParamForLane`, `_apply303Param`) untouched; existing 303 tests pass unchanged.
- `tsc -b`, `pnpm lint`, `lint:ratchet` (baseline only down), `CI=true test:unit`, `test:integration` if the native build is available; no `eslint-disable`, no skipped tests.
