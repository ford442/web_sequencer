- **Fixed by THIS session, genuinely new, not touched by either merged PR:**
  `perf-summary.json` was empty even on a fully green `test:perf` run, for two
  independent reasons:
  1. `scripts/collect-vitest-perf.mjs` read `VITEST_PERF_SUMMARY` from its own
     process env, but `vitest.setup.perf.ts` only sets that inside the vitest
     worker process — it never reaches the separate `node` invocation that
     collects it. The collector was silently overwriting vitest's real output
     with an empty stub every time. Fixed: default
     `handoff = process.env.VITEST_PERF_SUMMARY ?? outPath` (vitest already
     writes real content directly to `outPath`).
  2. `vitest.setup.perf.ts`'s `afterAll` wrote fresh per test FILE (Vitest
     resets its module registry per file even under `singleFork` +
     `fileParallelism:false`), so each file overwrote the previous file's
     samples instead of accumulating — whichever file finished last (often one
     with zero perf samples, e.g. `useAudioEngine.perf.test.tsx`) silently won.
     Fixed: `afterAll` now read-merges (reads existing file, appends this
     file's samples, writes back); a `globalThis`-keyed `Symbol` clears any
     stale file exactly once per whole `vitest run`.

  Verified: `rm -f perf-summary.json && CI=true pnpm run test:perf` exits 0,
