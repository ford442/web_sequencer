# #1659 PWA offline second load — state

Branch `fix/pwa-offline-boot-1659`, base `origin/main` 2e912b7 (the brief named 25e8bae; main had moved on).
Environment: Linux container, Node 22.23, pnpm 12, Emscripten 6.0.13 via `setup:emsdk`, Playwright 1.57 (chromium 143, firefox 144, webkit installed here with `install-deps`).

## Status: root cause found and fixed; offline test un-skipped on chromium, firefox and webkit.

## Hypotheses
| # | Hypothesis | Status | Evidence |
|---|---|---|---|
| 1 | Precache key mismatch (base path, query, `./` resolution) | KILLED | Instrumented worker, miss branch: same cache, 106 entries, `match(request.url as string)` = **hit** while `match(request)` = miss. Keys were fine. |
| 2 | `Vary` on stored responses makes `match(request)` miss | **CONFIRMED — root cause** | `vite preview` sends `Vary: Origin` on every asset. Chromium sends `origin: http://127.0.0.1:…` on same-origin `crossorigin` module-script/stylesheet requests (dumped from `request.headers` inside the worker); the stored entry came from the worker's own `fetch(url)` with no `Origin`. Controls: original worker + original manifest passes offline on a static host with no `Vary`; original worker fails on vite preview; adding `ignoreVary:true` fixes it; a page-side probe never reproduced it because `new Request()` drops the forbidden `Origin` header. |
| 3 | Manifest lacks something the boot path needs | PARTLY HOLDS (not the cause of ERR_FAILED) | Boot-time unhashed assets were absent offline: `osc/*`, `audioExport-*.wasm`, `hyphon_wasm_export_map.json`, `samples/vowels/manifest.json` (matched no runtime pattern). Engine health offline dropped `audioExport` wasm→js and added "Vowel samples off". Lazy JS chunks and CSS were all in the manifest. |
| 4 | Runtime assets fetched before the worker controlled the page never reached the runtime cache | HOLDS for the assets above | The first load is never controlled. `hyphon_native*`/`rubberband`/WAVs happened to be cached because INITIALIZE (after control) refetches them; a visitor who leaves before INITIALIZE would have had none. Fixed by precaching boot-critical unhashed assets by manifest (+2.92 MB; shell 4.27 → 7.19 MB, 106 → 147 entries). Pyodide (76 MB) and files > 2 MiB (ort wasm 23.8 MB) excluded. |
| 5 | Cache name / BUILD_ID disagreement after restart, or activate deleting the cache in use | KILLED | Worker log at offline time: `caches.keys()` = precache + runtime of the same id, 106 entries present. Name derives from the stamped script, so a restart gets the same names. Unit tests: activate keeps own-build caches, deletes only stale `hyphon-*`. |
| 6 | `withCorp()` re-wrapping yields a response the browser rejects | KILLED | `vite preview` sends CORP itself, so the re-wrap never ran there. Re-tested on a plain gzip static host sending only COOP/COEP (no CORP, no Vary): re-wrap ran, offline boot + playback + `crossOriginIsolated` all passed. |

Also found: **`context.setOffline(true)` does not stop the worker's own `fetch()`.** With only `setOffline`, the un-skipped test PASSED on the broken worker (the worker reached the live server). That is why three CI attempts could not localise it. The test now kills the origin.
WebKit: the recorded `page.reload()` "internal error" reproduces **only** when `context.setOffline(true)` is called; with the origin dead and no emulation WebKit reloads and boots. So webkit is NOT skipped; `setOffline` is applied on chromium/firefox only.
