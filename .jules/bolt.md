## 2024-04-26 - [Avoid Stale Closures When Memoizing Many Handlers]
**Learning:** When trying to memoize a large set of event handlers (like dozens of onChange handlers for Knobs) to prevent child re-renders, relying directly on prop dependencies in `useCallback` defeats the purpose as it creates a new function reference every time the prop changes.
**Action:** Use the `useRef` + `useEffect` pattern (or a `useLatest` hook) to hold the latest value of the frequently changing prop (like `params`), so the `useCallback` dependency array can be empty (or only rely on stable setters) while still accessing current data.

## 2024-06-03 - [MainSequencer Re-renders & Inline Function Traps]
**Learning:** In a highly interactive matrix like `MainSequencer` where multiple `SequencerRow` components (containing 32 steps each) exist, passing inline functions like `onPitchChange={onPitchChange || (() => {})}` causes every single row to re-render on *any* parent state update, because `() => {}` is a new reference every render. Also, including rapidly changing deeply nested objects like `pattern.sampler` in a `useCallback` dependency array breaks memoization for event handlers passed to 256+ SVG nodes.
**Action:** Always extract fallback inline functions to a stable reference outside the component (e.g. `const noop = () => {}`). For large data structures needed inside callbacks, use the `useRef` + `useLayoutEffect` pattern to capture the latest value without polluting the dependency array. Memoize dynamically created objects (like `selectionRange` props) passed to child components.
