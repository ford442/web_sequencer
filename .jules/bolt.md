## 2026-07-20 - GC Optimization in Step Handler Hot Path
**Learning:** High-frequency real-time execution paths (like `useStepHandler.ts` step loop) create severe main-thread GC pressure from transient array allocations (`.map`, `.filter`) and object spreads (`{ ...obj }`). Code review revealed that small object literals and spreads (like `bankParams` or `liveValues`) allocate frequently and should be preallocated.
**Action:** Use module-level scratch arrays and objects (e.g. `_midiScratch`, `_bankParamsScratch`) in synchronous hot paths. Clear them in place (`for..in delete`, `.length = 0`) instead of allocating new instances per step. Replace array mapping with preallocated `for` loops and in-place mutations (like rotation instead of `.shift()`).
