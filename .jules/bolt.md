## 2026-07-16 - Replacing .map().filter().find() in sequencer hot-path
**Learning:** In `useStepHandler.ts`, the `lockToSequencer` logic was evaluating an array pipeline (`seq.steps.map(s => (s ? i : -1)).filter(i => i !== -1)`) on every step trigger (high frequency, 60+ Hz during playback). This spawned multiple transient arrays during dense sequences and caused consistent main thread garbage collection (GC) overhead.
**Action:** Replaced functional array pipelines in performance-critical scheduler/sequencer logic with standard `for` loops and inline integer tracking (`firstActiveStep` / `targetStep`) to eliminate memory allocations entirely.
