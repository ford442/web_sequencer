## 2024-05-18 - Missing focus indicators and ARIA labels on dynamic warning banners
**Learning:** In dynamically injected warning banners (like `EngineDegradationBanner`), actionable buttons often lack sufficient `focus-visible` states and explicit `aria-label`s, especially when their text content updates dynamically (e.g. "Retry" -> "Retrying..."). This affects keyboard navigation significantly as focus rings are easily lost against colored banner backgrounds.
**Action:** When adding or auditing dynamic warning or degradation banners, always ensure the actionable elements include explicit `aria-label` properties that match the dynamic state, and apply high-contrast `focus-visible:ring-offset-*` classes that match the banner background to maintain clear keyboard focus indicators.
## 2024-06-25 - Using focus-visible instead of focus for keyboard accessibility
**Learning:** Consistently using `focus-visible` utility classes (e.g. `focus-visible:ring`, `focus-visible:border`) instead of just `focus:` ensures that focus rings and focus indicators only appear when navigating the UI via keyboard. A common pitfall is to apply `focus:` to buttons or interactive elements, which results in focus rings showing up during mouse clicks, creating a confusing and janky visual experience.
**Action:** When adding or updating focus indicators, always prefer `focus-visible` utilities (`focus-visible:ring-2`, `focus-visible:border-*`, etc.) to maintain standard keyboard accessibility behavior while keeping mouse interactions clean.
