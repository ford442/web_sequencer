# Changelog

## Unreleased

### Oscillators: a C++ filter (LP / BP / HP), usable by any oscillator (#1673)
- **New: the C++ kernel has a real resonant filter.** `emscripten/cpp_osc.cpp` gains a trapezoidal state variable filter (low, band and high pass; `f64` coefficients and state) behind four new exports in the same `public/cpp_osc.wasm` (`cflt_buf_ptr`, `cflt_configure`, `cflt_reset`, `cflt_process`). It is the bilinear transform of the same prototype as the RBJ biquads, so it sounds the same as the WASM OSC and Rust filters (noise through all three agrees to f32 rounding), and it stays smooth when the cutoff moves.
- **New: "C++" as a filter source for every oscillator.** `SynthParams.filterSource` is now `'native' | 'wam' | 'rust' | 'cpp'` (absent is still a native lowpass, so saved songs are unchanged). `cpp` runs the kernel's filter as an AudioWorklet stage (`cpp-filter-processor`) after whatever the synth plays: JS, WASM OSC, Rust, C++, DWGS, WebGPU, Pyodide, WAV. The Filter / Source selector gains a fourth button.
- **Placement:** the filter lives in the standalone `cpp_osc.wasm`, not `hyphon_native`: one more 2-page instance per voice that selects it, nothing in the voice module's heap, and a filter node never builds the oscillator's residual tables. `cpp_osc.wasm` is ABI 2; the release gate smoke-calls the filter.
- **No silent fallback.** If the C++ filter cannot run, the voice uses the native filter and says so under `filter-source:cpp`; it never borrows another engine's filter stage.
- **Verified** by `cppFilter.realWasm.test.ts` on the real binary (integration tier: needs `pnpm run build:wasm:cpp`, `build:wasm:wamfilter`, `build:wasm:rust`, `build:wasm:oscillators`), plus unit tests for the bridge, the selector, `Voice` routing and the hermetic module fixture. **Known:** as for the Rust filter, it is a separate node after the oscillator, offline bounces use the logged native fallback, and cutoff / Q / type are per-block (k-rate). See [BUILD_NOTES#cpp-filter](docs/wasm/BUILD_NOTES.md#cpp-filter).

### Oscillators: a Rust filter (LP / BP / HP), usable by any oscillator (#1672)
- **New: the Rust kernel has a real resonant filter.** `rust-audio/` gains an RBJ biquad (low, band and high pass; `f64` coefficients and state; no libm, so its own sin/cos, accurate to 1e-14) behind four new exports in the same `public/rust_osc.wasm` (`rflt_buf_ptr`, `rflt_configure`, `rflt_reset`, `rflt_process`). It replaces the retired bench crate's naive lowpass and sounds the same as the WASM OSC filter (noise through both kernels agrees to f32 rounding).
- **New: "Rust" as a filter source for every oscillator.** `SynthParams.filterSource` is now `'native' | 'wam' | 'rust'` (absent is still a native lowpass, so saved songs are unchanged). `rust` runs the kernel's biquad as an AudioWorklet stage (`rust-filter-processor`) after whatever the synth plays: JS, WASM OSC, Rust, C++, DWGS, WebGPU, Pyodide, WAV. The filter is independent of the oscillator shape and engine, and a host that bakes its own filter is told to bake none. The Filter / Source selector gains a third button.
- **Per-source degradation.** If the Rust filter cannot run the voice uses the native one and says so under its own degradation id (`filter-source:rust`; the WASM OSC filter's is now `filter-source:wam`, was `filter-source`), so one source working never clears the other's report.
- **Under the hood:** `WamFilter` is generalised into `WasmFilterStage` (pooled nodes, readiness probe, named failures) with a `RustFilter` on `loadRustOscModule()`, so the oscillator and the filter fetch and compile `rust_osc.wasm` once. `Voice` holds one wasm filter node at a time and hands it back when the source changes. **ABI:** `rust_osc.wasm` is ABI 2 (the export surface grew); the release gate also smoke-calls the filter.
- **Verified** by `cargo test` (22 host tests: coefficients vs libm, RBJ response shapes, 20 Hz stability, refused arguments, denormals) and `rustFilter.realWasm.test.ts` on the real binary (integration tier: needs `pnpm run build:wasm:rust` and `build:wasm:wamfilter`). **Known:** the filter is a separate node after `rust-*` rather than inside its worklet; offline bounces use the logged native fallback; cutoff / Q / type are per-block (k-rate), set at note start. See [BUILD_NOTES#rust-filter](docs/wasm/BUILD_NOTES.md#rust-filter).

### Oscillators: the WASM OSC filter is LP / BP / HP, and any oscillator can use it (#1663)
- **New: selectable filter type.** The AssemblyScript kernel's filter is no longer a lowpass hard-coded in `generate`. `assembly/biquad.ts` is one RBJ biquad with low, band (constant 0 dB peak, like `BiquadFilterNode`) and high pass; `generate` / `generateLoop` take a final `filterType`. A caller that passes the old seven arguments still gets the lowpass it always had; an unknown type renders 0 frames rather than quietly rendering a lowpass.
- **New: "WASM OSC" as a filter source for every oscillator.** `SynthParams.filterSource: 'native' | 'wam'` and `filterType: 'lp' | 'bp' | 'hp'` (both optional; absent is a native lowpass, so saved songs are unchanged). Choosing `wam` runs the kernel's biquad as an AudioWorklet stage (`assembly/wamFilter.ts` → `src/wasm/wamFilter.wasm`, 3.5 KB, one fixed page, no imports) after whatever the synth plays: JS, WASM OSC, Rust, C++, DWGS, WebGPU, Pyodide, WAV. A host that bakes its own filter into its table is told to bake none, so exactly one filter shapes the sound. The same resonance knob sounds the same on either source (dB Q for LP/HP, linear for BP).
- **No silent substitution.** If the WASM filter cannot run (no worklet, wasm missing or rejected, offline render, lost mid-session) the voice runs the native filter and reports it once per cause: console, telemetry, the degradation store and a notice under the selector. A backend that cannot bake the asked response is skipped with a logged reason instead of baking a lowpass.
- **UI:** a Filter row (LP / BP / HP) and a Source row (Native / WASM OSC) under the waveform picker for SYNTH A and B, shown for the families that run through the voice filter (not 303 / Prophecy / Macro, which own theirs).
- **Verified** in real Chromium against the RBJ formulas and a real `BiquadFilterNode` (0.000 dB error at every probe) and by `wamFilter.realWasm.test.ts` / `WasmOscillator.realWasm.test.ts` (integration tier: need `pnpm run build:wasm:wamfilter`). **Known:** offline bounces use the logged native fallback for now; cutoff / Q / type are per-block (k-rate), set at note start. See [BUILD_NOTES#wam-filter](docs/wasm/BUILD_NOTES.md#wam-filter).

### Oscillators: WASM OSC (`wam-*`) is band-limited, loops cleanly, and no longer traps (#1663)
- **Better sound.** The AssemblyScript kernel now band-limits at the source: PolyBLEP on the saw and square edges, PolyBLAMP on the triangle's corners. Energy between the harmonics drops by **~18 dB** on saw and square at every pitch (a 1 kHz saw: -16 → -34 dB) and by up to **12 dB** on the triangle at high pitch. Phase is `f64` and computed from the frame index, and the biquad is `f64` transposed DF II (same lowpass, same cutoff/Q meaning), so a 20 Hz cutoff no longer drifts in `f32`.
- **Fix: the looped table clicked on every wrap.** 2 s at C4 is 523.26 cycles, and the filter started from rest. New `generateLoop` rounds to whole cycles (pitch moves < 0.01 cent) and runs the filter to steady state first; `WamWasmBackend.renderLoop` uses it. One-shot `generate` is unchanged in length and onset: a note is still exactly `floor(rate * dur)` frames.
- **Hardening.** NaN, zero, negative or infinite pitch/duration/rate return 0 frames instead of DC or garbage; NaN cutoff/Q fall back to an open filter; pitch is capped below Nyquist; a render too long for the module's memory is truncated, never an out-of-bounds trap. The bridge grows memory ahead of renders over ~60 s. The kernel never writes outside the range it returns.
- **Unchanged:** every `asc` flag (`simd` + `bulk-memory`, no WasmGC, no relaxed SIMD, no threads), the 384-page budget, the 7-argument `generate` ABI, the waveform ids and the fallback order. Cost per 2 s table in V8: saw 0.5 → 0.6 ms (0.8 as a loop table), sine 1.3 → 1.9 ms (2.3 as a loop table), paid on the main thread when a voice builds its source. New `WasmOscillator.realWasm.test.ts` (integration tier) holds the margins above on the real binary. See [BUILD_NOTES#wam-osc](docs/wasm/BUILD_NOTES.md#wam-osc).

### Oscillators: DWGS is a real mode (#1666)
- **New: DWGS.** Korg's *Digital Waveform Generator System*, recovered from the only trace the mode had left: its panel art (Korg-badged, WAVEFORM SOURCE = SAW / SQR / NOISE / DIGITAL WAVEFORM), deleted as an orphan in #1294 and now restored. It is a waveform oscillator built on additive synthesis, not the digital waveguide the initials suggested. 17 waves: `dwgs-saw`, `dwgs-sqr`, 14 harmonic-recipe digital waveforms (piano, e-piano, clav, organ, brass, reed, strings, guitar, dist, bass, digibass, bell, vox, sine) and `dwgs-noise`, whose colour follows the keyboard. All recipes are original. See [docs/audio-engine/dwgs-oscillator.md](docs/audio-engine/dwgs-oscillator.md).
- **How:** a scalar `no_std` Rust kernel (`dwgs-audio/` → `public/dwgs_osc.wasm`, 28 KB, zero imports, fixed 128 KiB per voice) renders each recipe **additively per sample** in a `dwgs-osc-processor` AudioWorklet, one per synth voice. Only harmonics below 0.45 fs are summed (faded in at the edge), so nothing aliases at any pitch, and slides stay continuous. Waves are matched in RMS. Offline bounces run the same kernel and are bit-identical, noise included.
- **Fallback:** DWGS heads the backend order as an *entry-only* backend. A `dwgs-*` part without its worklet plays its wave's nearest basic shape on the next live engine (reported), and no other family ever lands on DWGS.
- **UI:** a DWGS oscillator type (lime, badge DW) whose variant panel mirrors the hardware: a Source row (SAW / SQR / NSE) and a Digital grid.
- **Known:** additive synthesis costs more than a BLEP. ~17–20 µs per 128-frame block for low notes in V8 (≈ 0.7 % of the audio thread per voice; the Rust OSC is ~0.6 µs). There is no in-kernel filter yet (#1674); the voice's biquad follows, as for every `Voice` family.

### Oscillators: `cpp-*` is a real C++ engine (#1665)
- **New: C++ OSC.** `cpp-saw` / `cpp-sqr` / `cpp-tri` / `cpp-sin` render through a C++ kernel (`emscripten/cpp_osc.cpp`) for the first time. Before this, `cpp-*` had no renderer: it was offered, played an `OscillatorNode`, and since #1294 was rewritten to `wam-*`. Each synth voice gets its own `cpp-osc-processor` AudioWorklet node. The kernel band-limits with a 32-tap linear-phase windowed-sinc BLEP/BLAMP: the worst alias below 16 kHz is ≈ −90 dB for a 3.5 kHz saw at 48 kHz, against ≈ −20 dB for a naive one. Note onsets are band-limited too.
- **Placement:** a standalone em++ module, `public/cpp_osc.wasm` (11 KB, zero imports, fixed 128 KiB per voice, no JS glue), in its own `cpp-osc` native world. It is not inside `hyphon_native`, whose heap is sized for its own voices. See [BUILD_NOTES#cpp-osc](docs/wasm/BUILD_NOTES.md#cpp-osc).
- **Fallback order** is now WebGPU → Rust OSC → **C++ OSC** → WASM OSC → Pyodide → WAV PCM → JS. The C++ kernel is scalar, so a `rust-*` part on a browser without WASM SIMD now gets a live band-limited voice instead of the AssemblyScript table. A `cpp-*` part with no worklet steps to the table. Every step is published, none is silent.
- **Saved songs:** `cpp-saw/sqr/tri/sin` load as written. `cpp-rand`, which never made a sound of its own, is rewritten to `cpp-saw` and the rewrite is reported.
- **Known:** 16 samples (0.33 ms at 48 kHz) of fixed latency, and Gibbs overshoot to ≈ 1.17 on saw and square edges. Both come from the long band-limiting residual. The C++ filter is #1673.

### PWA: the app shell boots and plays offline on its second load (#1659)
- **Fix: an installed app white-screened offline.** Every precached JS/CSS file missed `cache.match(request)`. The shell was stored from the worker's own `fetch(url)`, which has no `Origin` header; Chromium sends one on same-origin `crossorigin` module-script and stylesheet requests; and a host that answers with `Vary: Origin` (`vite preview` does) makes `Cache.match` honour the difference. The worker then fell through to the network and rejected, so the bundle failed with `net::ERR_FAILED` while sitting in the cache. All of `public/sw.js`'s cache lookups now ignore `Vary`; an uncached request offline gets an explicit `Response.error()`; shell keys are absolute URLs under the scope.
- **Fix: the boot assets the page fetched before the worker controlled it were never cached.** `hyphon_native*`, `rubberband.wasm`, the AssemblyScript wasm engines, the default oscillator WAVs, `osc/` art, the vowel pack and the WASM export maps are now precached by manifest (+2.9 MB at install: shell 4.3 -> 7.2 MB). Offline, `audioExport` no longer drops to its JS fallback and "Vowel samples off" no longer appears. Pyodide (~76 MB) and files over 2 MiB stay on the runtime cache-first path; the build prints which files the cap leaves out.
- **Tests:** `tests/pwa.spec.ts`'s offline second-load test is un-skipped on Chromium, Firefox and WebKit. It kills a private preview server instead of trusting `context.setOffline`, which does not stop a service worker's own `fetch()`. New `src/__tests__/serviceWorker.test.ts` runs the real `sw.js` against a fake Cache Storage with `Vary` semantics (28 tests; the `Vary` regression fails on the old worker). See [the ADR](docs/deployment/ADR_PWA_SERVICE_WORKER_COEP.md).

### Audio recording, phase 1: raw input and lossless takes in OPFS (#1498)
- **Input**: the Engine HUD has an **Audio input** picker beside **Audio output**. A take opens its device with `echoCancellation`, `noiseSuppression` and `autoGainControl` off, and the picker shows `track.getSettings()`: what the browser actually kept. A stored device that is gone opens the default input and says so.
- **Recorder**: a new `recorder-processor` worklet captures from a context frame to a context frame (sample-exact inside a block) into a SharedArrayBuffer ring tagged with the first sample's frame. A new take writer worker drains it into OPFS through a `FileSystemSyncAccessHandle`, as a 32-bit float WAV that becomes RF64 past 4 GiB. Without cross-origin isolation the worklet posts chunks on a port handed straight to the worker. Either way the audio never crosses the main thread: in Chromium, a 40 s stereo take (15.4 MB on disk) moved the page heap by at most 46 KB. Frames a full ring drops are written as silence, so a take keeps its timing. A stop that arrives late still ends the take on its frame. The recorder is its own worker and is not linked into `hyphon_native.wasm`.
- **Recovery**: the header is patched and flushed once a second, so a killed tab leaves a valid WAV up to the last flush. On the next load, a notice offers each unfinished take: **SAVE WAV** (trim, patch, download) or **DISCARD**. The notice and recorder load only when an OPFS `takes/` folder exists.
- **Sampler REC** records through this path and decodes the WAV losslessly into the bank. It no longer uses `MediaRecorder` / webm. A browser that cannot record shows `Rec unsupported: <reason>` and does not fall back. See [audio-recording.md](docs/audio-recording.md).
- **Bundle** (a web build without native artifacts): the entry chunk grows by 4.7 KB raw (1.2 KB brotli): the picker, the support check and the recovery gate. The recorder, worker, worklet and input code are lazy chunks. The brotli `dist/assets/` total goes from 985,885 B to 997,433 B, over the 990,000 B row. The row is raised to 1,000,000 B in its own commit.
- **Fix**: `engineTelemetry.test.ts`'s snapshot fixture gains #1650's `stepLookaheadMs`, so `tsc -b` passes again.

### Boot gate and drum export: Python is a table generator, not the core
- **`INITIALIZE SYSTEM`** enables once the `hyphon_native` probe settles: `READY`, or `JS FALLBACK` when the module is missing, corrupt or unreachable for 10 s (the voices run their documented JS / Web Audio fallbacks and the failure is already a degradation report). Python never gates it, so a missing `public/pyodide/` or a Python timeout no longer blocks a kick on step 1.
- **Python table engine** (was "CORE (PYODIDE)") is its own overlay line: `NOT REQUESTED` with a **LOAD** control, `LOADING...`, `LOADED` or `FAILED`. It loads on demand through `src/pyodide/pythonEngineStore.ts`: a `pyodide-*` waveform on a synth, `requestPythonEngine()` for an explicit Python render, or **LOAD**. The first paint does not fetch `pyodide.js` or the bootstrap chunk. A timeout or load failure is a retryable `python-table-engine` degradation report, and `pyodide-*` waveforms fall back through `BackendRegistry` as before.
- **Drum export is the live kit.** `renderDrumToBuffer` renders through the same `drumkit_*` voice `DrumKitEngine` plays (`OfflineDrumKitEngine`, on the shared offline `hyphon_native` instance, with the live trigger arguments), and falls back to `DrumKitEngine`'s own Web Audio kit when the module is unavailable. Pattern drum bounces no longer take the Python drum freezer. `generate_kick` / `generate_snare` / `generate_hat` run only for an explicit `renderDrumToBuffer(..., { python })`. The signature is now `(sound, params, sampleRate?, { kit?, python? })`.
- **Bundle**: the entry chunk grows by 167 B raw; JS + CSS across all chunks grows by about 3.2 KB raw (1.6 KB brotli), from the offline drum renderer and the Python store, which includes chunk reshuffling. No vendored Pyodide, native or audio bytes are added to `dist/`, and no `dist-budget.json` row is raised.

### Audio tracks, phase 2: waveforms and clip editing (#1629)
- **Peaks**: every piece of media gets a min / max pyramid (int16, 256-frame buckets, then halving to one bucket), stored next to it as `media/<sha256>.peaks` behind a deterministic header. The import builds it from the audio it just decoded. Media without a current peaks file (imported before this change, or an older format) is rebuilt in a new `mediaPeaks.worker.ts` that pages the audio out of the media store, so the page never holds the audio to draw it. Without a worker, or on the in-memory backend, the build runs on the main thread a page at a time. The cache holds 64 pyramids at most.
- **Waveforms**: ARR draws the audio lanes on one canvas behind the clip blocks with the piano roll's quad renderers (WebGPU on the shared device, Canvas2D fallback). The canvas is sticky and only as wide as the lanes in view, and it redraws only on scroll, edits, drag previews or arriving peaks. Each pixel column is the min / max of the source frames it plays, swing included, scaled by the clip gain and fades. Columns past full scale are drawn red, and fades are shaded above their ramp. `useQuadCanvas` is the backend / frame-loop hook the piano roll now shares.
- **Editing**: an audio clip's top handles drag its fade-in, fade-out and gain (Shift: finer). Alt + drag slips the audio under the clip (`offsetFrames`, on the grid; with Shift, to the pixel). Alt + click splits any clip at the snapped step, and S or Ctrl/Cmd+E splits at the playhead (or the middle when the playhead is elsewhere). ↑ / ↓ nudge clip gain by 1 dB (Alt: 0.1 dB). The inspector edits fades and slip in milliseconds and has **SPLIT** for both clip kinds. Every edit previews locally and commits once, as one undo step: "fade in clip", "fade out clip", "slip clip", "split clip", "Clip gain 0 dB → -3 dB". `updateClip` keeps an edited audio clip valid (whole frames, gain clamped to −96…+24 dB, a zero fade left out). See [audio-tracks.md](docs/audio-tracks.md).
- **Bundle** (a web build without native artifacts, against #1645): the entry chunk does not grow (+9 B brotli). The lazy chunks grow by about 10.1 KB brotli (32 KB raw): the ARR chunk (editing, scene, painter), the media chunk (peaks, cache), and a new 13 KB raw worker chunk that carries its own copy of the media store. The brotli `dist/assets/` total goes from 995,604 B to 1,005,731 B against the 990,000 B row, and the raw total from 4,253,988 B to 4,286,051 B against 4,280,000 B. This change does not raise either row.

### Collaboration, phase 2: the document is the source of truth, with per-editor undo (#1597, #1628)
- **Stores bound to the doc**: the pattern, instrument patches, track storage, transport / mixer, arrangement, audio tracks, session, automation lanes, note FX and patch bay are views of the project's Yjs document (`collab/appBindings.ts`), in normal mode as well as `?collab=local`. Saves read the bound fields back through the codec, so `SavedSongData` is an import / export format. Two tabs on `?collab=local` edit one song.

Ctrl/Cmd+Z, Shift+Z, Ctrl+Y and the panels' undo buttons go through it, and `useUndoRedo.ts` and the snapshot stacks are gone. A gesture is one step (eight quick grid clicks are "paint 8 steps"), each co-producer tool call is one step, and a tab's undo never takes back another tab's or the co-producer's edits. **HIST** in the bottom bar lists both editors' labelled steps, with jump-to.
- **God-hook splits**: `useAppState.tsx` 966 → 387 lines, `useSongStorage.ts` 986 → 361 (`useSongStorage/{save,load,migrate,export}.ts`), and `src/constants.ts` folded into `src/constants/`. The module-size gate is a ratchet: a listed file that grows fails CI.
- **Follow-up**: the two-tab acceptance spec (`tests/collab-undo.spec.ts`) now passes against a real native build. Audio-track edits get history labels ("Audio 1: Fader 0 dB → -6 dB", "Clip gain 0 dB → -3 dB", "split clip"; a head trim is "resize clip", not "move clip"). An atom value with a `__proto__` key no longer loses it on the peer that receives it (the codec's convergence property test failed on it now and then). The ESLint ratchet and `audioRuntimeGuards` are green again.

### Audio tracks, phase 1: audio clips on the arrangement timeline (#1629)
- **Schema v6**: `ArrangementClip` is now a union on `kind`, with pattern clips (unchanged, `kind` absent) and audio clips (`mediaId`, `offsetSteps` + `offsetFrames` slip, `gainDb`, fades, `warp`). The song gains `audioTracks` (eight at most, `audio-1` … `audio-8`) and a `media` table. The v5 → v6 migration is the identity: a v5 song loads unchanged, with no audio tracks. `placeClip` / `updateClip` / the new `splitClip` handle both kinds under the one-clip-per-track rule. A split never needs the tempo, because an audio clip's head trim moves `offsetSteps` like a pattern clip's.
- **Collab**: `audioTracks` lives in the `mixer` map and `media` in `assets`, both bound through `audioTrackStore`. An import is one undo step, and concurrent imports from two tabs both land. The codec's every-field fixture carries the new fields.
- **Media store**: `media/<sha256>.f32` (planar float32 behind a deterministic JSON header), content-addressed and shared across projects on the ProjectStore backends, which gained range reads. WAV / RF64 decode losslessly in TypeScript, and other formats through the browser decoder.
- **Import**: drop audio files on the ARR timeline (on an audio lane at the snapped step, or anywhere for a new track), or use **IMPORT** / **+ AUDIO**. Audio lanes have M / S and an inspector for clip gain, length, and the track's fader and pan.
- **Playback** (`warp: 'off'`): a new `audio-clip-processor` worklet with one stereo output per audio track, each output cabled into a new `audioTrackVoice` socket in the stock patch (dry into the master gain, so inserts can be cabled in). Voices are prepared a second ahead and armed on their step's exact frame, and fed a page at a time from the media store through SAB rings (posted pages without cross-origin isolation). Tempo changes, seeks, mute / solo and late pages keep clips on the grid. The player loads lazily, so the entry chunk did not grow.
- **Stems**: each audio track exports as `stems/audio-N.wav` and joins the master stem. The offline render runs the worklet's voice code, and a test null-tests it against the live path sample for sample.
- **Bundle**: about 12.7 KB brotli of new code, all in lazy chunks or the worklet, plus about 4 KB of chunk overhead from keeping the player out of the entry chunk (which shrank by 0.7 KB). The brotli `dist/assets/` total is 995,001 B, 5,001 B over `dist-budget.json`'s 990,000 B row, which this change does not raise. See [audio-tracks.md](docs/audio-tracks.md).

### Session packs: a versioned `.hyphonpack.json` format, import / export, and three new starters
- **Format**: a pack is metadata, a `SessionDocument`, the pattern slots its clips point at and optional SYNTH A / B settings, as plain JSON (`format: "hyphon-session-pack"`, `formatVersion: 1`). The contract is `docs/schemas/session-pack.schema.json`, generated from `src/session/pack/schema.ts` (`pnpm run gen:session-pack-schema`; `check:session-pack-schema` is part of `pnpm lint`). The importer runs ajv's standalone output, so the app ships no ajv, and no dependency was added. `Note` and `PhonemeData` are listed field by field in a `Record<keyof …>` table, so a new note parameter fails the build until the format knows it. See [session-pack-format.md](docs/session-pack-format.md).
- **Import boundary**: size → `JSON.parse` → pure migrations (`PACK_MIGRATIONS`) → closed-schema validation → reference checks (clip and scene ids, a scene naming a clip on another track, non-empty clips with no pattern, unplayable pitch names) → a fresh `SessionPack`. Unknown versions, unknown fields (URLs, scripts, `__proto__`), out-of-range instrument values and files over 4 MiB are refused with a path and a sentence. Nothing in a pack is executed or fetched, and a failed import changes nothing.
- **Session Launcher**: **IMPORT PACK…** shows a preview (name, scenes, tracks with clip / pattern / note counts, the instruments the pack asks for and what they need, the pattern slots it would collide with) and loads only on **LOAD PACK**. **EXPORT PACK** writes the live session after proving the file imports back; round trips keep the session document, every slot, notes, scenes, sampler banks and the supported instrument parameters. A pack id that collides with a starter or an earlier import gets the next free `-2`, `-3` suffix. A pack slot that would replace a different pattern of the song is kept out of the way by default (moved to the lowest free slot, clips and scenes repointed) or replaces it on request.
- **Starters as data**: Ambient Drift (macro chords chained with follow actions, wandering bells), Broken Beat Workbench (syncopated cells, groove-timed hats, toggled layers, a one-shot fill) and Vocal Sampler Booth (phrase, call and reply, sliced chops, reverse swell, held stutter), built from the app's own pattern tools with fixed seeds. Each is a lazily loaded JSON chunk that goes through the importer. The five built-in starters are unchanged.
- **Keyboard fix**: the launcher's dialog-wide key handler swallowed Enter, Space, arrows, Delete and Backspace from every child, so the header buttons could not be activated from the keyboard, the quantization select lost its arrows, and typing in a text field would have stopped all clips. Those keys now drive the clip grid only when focus is in it.
- **Hardening**: a pack nested more than 64 levels deep (`PACK_LIMITS.maxDepth`; real packs are 7) is refused with a sentence before the migration runner's deep copy or the error formatter can overflow the stack, so `parseSessionPackText` really never throws. A number JSON writes as `1e999` is reported as "must be a finite number, got Infinity" instead of "got null". The launcher now turns a rejected import / load / export action (the lazy importer chunk failing to download, say) into an alert instead of silence.
- **Bundle**: the importer is a lazy chunk (about 14 KB brotli) and the starters add about 5 KB brotli; the entry chunk grows about 3.6 KB brotli. `dist-budget.json`'s two `dist/assets/` total rows were raised in their own commit.

### Patch bay: low-pass filter mode, standard (RBJ) vs openrb / ReBirth
- **Mode parameter on low-pass nodes**: `BiquadFilterConfig.filterMode` is `rbj` (the browser biquad, the default) or `openrb`. The palette offers it, and a selected low-pass node has a live **Standard (RBJ) / openrb / ReBirth** switch. Both filters run in parallel behind a 20 ms crossfade (`LowpassModeSwitch`), so A/B comparison needs no rebuild. Anything that can be cabled through a low-pass can use either mode. Offline renders follow the same path.
- **openrb mode is ReBirth 2.01's PCF low-pass**, run with its envelope at rest. Upstream openrb-338's coefficient table (8 × 512), smoother and 2-pole filter are extracted into `openrb338/src/pcf_lp.rs`, with an adapter (`lowpass.rs`) for Hz/Q, the host rate and the output gain, and an optional `openrb_lp_*` export group in `openrb338.wasm`. At 44.1 kHz the table is bit-identical to upstream and the output matches upstream's `Pcf` bit for bit, native and wasm, in every chunking (`pnpm run verify:openrb338`). Other host rates shift the table index to keep the pole frequency; they are not bit-exact.
- **Opt-in, like the openrb-338 voices**: the module is GPL-3.0-only and not bundled. A build loads it only when `VITE_OPENRB338_WASM_URL` is set. Without it, openrb mode plays RBJ, the patch bay says why, and the patch keeps the mode. See [openrb-lowpass.md](docs/audio-engine/openrb-lowpass.md), which also covers the floating-point matching expectations.

### openrb-338 TB-303 as a WASM module: extraction spike (#1537)
- **New world `openrb338/`**: openrb-338's `Tb303` and the tables it reads, extracted into a standalone Rust crate from upstream rev `88a1770`. The DSP code is unchanged. A thin adapter turns MIDI notes, velocity accents, legato slides and the shared normalized 303 params into ReBirth step bytes and knob positions, and a C ABI matches `Openrb338Exports`. It builds to a 40 KB `openrb338.wasm` with no imports. **GPL-3.0-only**, with its own `LICENSE`. The build is opt-in (`pnpm run build:wasm:openrb338`), its output is gitignored, and it is not part of `build:native` or `public/`.
- **Bit-exact at 44.1 kHz**: `pnpm run verify:openrb338` checks the tables, the native adapter and the wasm module, through its C ABI from Node, against upstream `orb-engine` at the same revision, sample for sample. The check covers 7 scenarios (both sound models, accents, slides, rests, knob sweeps, mode switches, stop) and four render chunkings. Other host rates are resampled and stay within 0.01 dB of the reference level. The cost is about 1–2 µs per 128-frame quantum.
- **Documented** in [openrb338-voice.md](docs/audio-engine/openrb338-voice.md): the ABI, the divergences (host rate, rest steps, how Hyphon schedules slides) and the integration plan for the `Open303EngineSelection` route. The voices still play Stock Open303 until the worklet loads the module.

### One note-name grammar for the parser, the AI song format and the agent (#1493)
- **One pattern**: `NOTE_NAME_SOURCE` in `musicTheory.ts` is the AI-song validator (`isValidNote`), the generated `docs/schemas/ai-song.schema.json` pattern and the co-producer's `edit_pattern` schema. A name the file formats call valid is a name `noteToMidi` turns into a pitch. The AI format now takes what the parser takes: a flat or sharp, a doubled one (`##`, `bb`, `x`, `𝄪`, `𝄫`, `♯`, `♭`), and octaves -1 to 9 (`Eb3`, `Fx3`, `C-1`). Strings are stored as written.
- **Tighter than before**: at most one accidental, of one kind. `C#b4`, `C###4` and `E##########4` used to parse (as 60, 63 and 74); they are not note names now. The pitch must be MIDI 0–127 (`C-1`–`G9`): `G#9`–`B9` used to parse as 128–131, which no MIDI data byte can hold, and are now refused rather than clamped. `edit_pattern` checks the range too, since a pattern cannot.
- **New**: `parseNoteName()` returns `{ pitchClass, octave, midi }` (the octave of the sounding pitch: `Cb4` is B3) for code that labels or colours a name. `noteColors` uses it, so `C-1` gets a colour and the second regex is gone.
- **Exports say what they left out**: SMF and RBS export leave a name that is not a note out of the file (no note 0) and add a warning such as `2 notes were left out because the name is not a note ("Hb4", "G#9").` A blank name is a rest and is not counted.
- **Fix**: a chord inversion counts the voices that sound. A chord with one name that does not parse used to rotate its other voices twice, which transposed it an octave instead of inverting it.

### Real-time control plane, phase 2: the main thread writes a voice's own ring; 303 and Prophecy on the bus (#1497)
- **One ring layout for both languages**: the event ring's header joins `emscripten/core/event_schema.json`, and `hyphon::EventRing` now uses the same bytes as `src/shared/rt/eventRing.ts` (generated `EventRingHeader`, with `static_assert`s on every word). A ring can sit at any offset of a buffer.
- **No copy on the pthread build**: each native voice has an inbox ring, and `prefix_event_inbox` returns its address. The drum and Prophecy worklets offer it in their `ready` message. The engine's route then writes records straight into hyphon_native's shared memory, and the C++ voice takes them at block start. Before the voice is ready, and on the single-threaded build, records go as one batched message per tick.
- **303 and Prophecy notes and params are records**: `Open303Oscillator` and `ProphecyOscillator` no longer post a message per note, param or stop. The 303 worklet routes each record to the voice its engine selection picks. A 303 param now reaches every voice the part owns, so an engine switch can never leave the new engine with stale params.
- **A stop is a record**: the new `CANCEL_NOTES` type drops the notes and hits queued before it, and keeps those sent after it. A stop followed by a restart in the same task now keeps the restart's notes on every transport. Drums, Prophecy and the 303 all stop this way.
- Nine per-event `port.postMessage` call sites are gone. See [VOICE_CORE.md#control-plane](docs/wasm/VOICE_CORE.md#control-plane).

### Real-time control plane, phase 1: one event record, a shared-memory ring, drums on it (#1497)
- **One schema for both languages**: `emscripten/core/event_schema.json` defines the 32-byte event record (frame, type, target, value, four args) and its types. `pnpm run gen:native-types` generates `hyphon::Event` (`emscripten/core/event_layout.h`, with `static_assert`s on its size and offsets) and the TypeScript `EventWriter` / `EventReader` (`src/shared/rt/eventLayout.ts`). `pnpm lint` and `check:exports` fail when either is stale. New record types, not yet handled by any engine: `PARAM_RAMP`, `MUTE`, `NOTE_EXPRESSION`.
- **Transport**: a lock-free SharedArrayBuffer event ring where the pthread profile runs, and batched `postMessage` (one transferred buffer per tick, not one message per event) on WebKit and on pages that are not crossOriginIsolated. Producers use one `EngineEventSink` interface on the main-thread `EventBus` and never branch on the transport. When the ring is full it drops the newest record and counts it. Hot producers stage records in a Float64Array (`bus.stage` + `commit`) and the worklet decodes with `popInto`, so no number is boxed: a perf test measures 3.3 KB of heap over 100k records.
- **Drum hits go through it**: `DrumKitEngine` no longer posts a message per hit. Each hit is a pan record plus a trigger record on the hit's frame, and a transport stop flushes queued hits to the worklet before it cancels them. Timing is unchanged: a kick through either transport is sample-identical to the old message. See [VOICE_CORE.md#control-plane](docs/wasm/VOICE_CORE.md#control-plane).

### Flat note names play at their pitch (#1466)
- **Fix**: `noteToMidi` understood only sharps, so `Eb3`, `Bb3`, `Cb4`, `F##3` and `C-1` all parsed as MIDI 0 (≈ 8 Hz), live and offline. The AI reference song (`full.json`) has five such notes. ### Real-time high-fidelity TB-303 — live A/B + editable diode ladder (Phases L2/L3)
- **Live A/B** (L2): a part on `live-highfid` can arm **A/B vs stock**. The same worklet plays Stock Open303 (A) and the diode ladder (B) from one note stream on two outputs. - **Lazy and stock-safe**: nothing is allocated until A/B is armed on a live-highfid part, and there is no second oscillator, WASM module or `hyphon_native` heap. The CPU gate still only trips the high-fid side and collapses the blend to A; the stock side's notes and profile are untouched.
- **Freeze of an A/B part records one side**: high-fid at blend ≥ 0.5, stock below. Blends are not frozen until the offline graph compiler (#1235) can render both.
- **Editable diode-ladder coefficients** (L3): transistor mismatch, decay curve, accent coupling and filter tracking are new `highfid303_set_param` ids (14–17), mirrored in the TS offline engine.
